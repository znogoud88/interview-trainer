## Что это
**Коротко:** CSS гниёт, потому что он глобальный и каскадный: любой селектор может задеть любой элемент, удалять правила страшно, поэтому только добавляют и перебивают. Лечение: изоляция (CSS Modules, scoped, Tailwind-утилиты), плоские селекторы без вложенности и без `!important`, токены вместо магических значений, линтер и coverage, чтобы мёртвое удалялось. Соглашение и структура важнее конкретного инструмента.

Как организовать, чтобы не гнило:
- Структура и порядок: токены → reset/base → компоненты → утилиты. Лучше явно через `@layer`.
- Именование: BEM или модули, один класс на элемент, вложенность не глубже 2. `!important` это симптом войны специфичности, а не инструмент.
- Стили лежат рядом с компонентом и умирают вместе с ним.
- Токены: `var(--space-m)`, не `13px`. Магические числа это будущие «а почему тут 13?».

**CSS Modules**: файл `Button.module.css`, бандлер переписывает `.primary` в `.Button_primary_x7f3a` и отдаёт объект `styles.primary`. Имена локальные, глобальных конфликтов нет, стили привязаны к компоненту: удалил компонент, удалил CSS. Trade-offs: динамика только переключением классов, глобальное через `:global`, стили тегов всё равно глобальные. Против styled-components/CSS-in-JS: модули это обычный CSS с zero runtime, работают с RSC; CSS-in-JS даёт стили от пропсов, но платишь runtime и сложностью SSR/streaming.

**Tailwind**: утилиты прямо в разметке, тема через токены (spacing, colors) даёт консистентность, в проде только использованные классы, нет мёртвого CSS, не нужно придумывать имена. Минусы: простыня классов в JSX, повторы, читаемость. Лечится компонентами (`<Button>`, а не копипаста 30 классов), вариантами через `cva` плюс `clsx`/`tailwind-merge`, а не `@apply` везде (это возвращает обычный CSS без его плюсов). **Tailwind v4**: CSS-first конфиг (`@import "tailwindcss"; @theme { --color-brand: ... }` вместо `tailwind.config.js`), токены становятся обычными custom properties, движок Oxide на Rust заметно быстрее, автоопределение контента, нативные каскадные слои.

**Аудит старого CSS**: DevTools → Coverage показывает неиспользуемые правила на текущей странице. Инвентаризация цветов и отступов (40 оттенков серого превращаются в 5 токенов). Инкрементально: переписываем то, что трогаем, не big bang. `stylelint` с правилами (нет `!important`, лимит вложенности, только токены) как защита от регресса. Visual regression tests перед чисткой.

## Пример
```tsx
// CSS Modules
import s from './Card.module.css';
<div className={clsx(s.card, active && s.active)} />

// Tailwind с cva: варианты в одном месте, разметка чистая
const button = cva('rounded px-4 py-2 font-medium', {
  variants: { intent: { primary: 'bg-brand text-white', ghost: 'bg-transparent' }, size: { sm: 'text-sm', lg: 'text-lg' } },
});
<button className={button({ intent: 'primary', size: 'sm' })} />
```
```css
/* ❌ вложенность и id: никто не перебьёт без !important */
#app .page .list li a.active { color: red !important; }
/* ✅ */
.nav-link--active { color: var(--color-accent); }
```

## Подводные камни
- CSS Modules не спасают от `:global` и от стилей на тегах (`a { }`): они по-прежнему глобальные.
- Tailwind без токенов в теме (`mt-[13px]` на каждом шагу) теряет главный плюс: консистентность.
- Tailwind находит классы сканированием исходников: `className={'bg-' + color}` он не увидит, класса в проде не будет.
- Coverage считает по одной странице и одному состоянию: hover, модалки, другие роуты не учтены, удалять по нему вслепую нельзя.
- Красный флаг: «добавляем !important, когда не работает» или «Tailwind это inline-стили». Интервьюер ждёт слово trade-off и понимание, какую проблему решает каждый инструмент.

## Вопросы вдогонку
- **CSS Modules или styled-components?** Модули: zero runtime, обычный CSS, RSC-friendly. CSS-in-JS: стили от пропсов, но runtime и SSR-сложности. Тренд: zero-runtime (vanilla-extract, Panda, Tailwind).
- **BEM ещё актуален?** Как соглашение в глобальном CSS да; в модулях и Tailwind не нужен, изоляцию даёт инструмент.
- **Как Tailwind убирает мёртвый CSS?** Генерирует только классы, найденные в исходниках, поэтому финальный CSS обычно меньше 10-20 КБ.
- **Зачем stylelint?** Запретить `!important`, глубокую вложенность, магические цвета, задать порядок свойств; ловит регресс в CI.
