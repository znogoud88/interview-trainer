## Что это
**Коротко:** hreflang говорит Google, какая версия страницы для какого языка и страны, чтобы австрийцу показали `/de-at/`, а не `/en/`, и чтобы версии не конкурировали между собой как дубли. Три классические ошибки: нет взаимности (de ссылается на en, en на de нет), забыт `x-default`, hreflang указывает на неканонический URL. Структура URL для стран это отдельный trade-off: subfolder (`site.com/de/`), subdomain (`de.site.com`) или ccTLD (`site.de`).

Как работает hreflang:
- На каждой странице перечисляются все её языковые версии, включая саму себя: `<link rel="alternate" hreflang="de-AT" href="https://site.com/de-at/shoes">`.
- Код: язык по ISO 639-1 (`de`), опционально регион по ISO 3166-1 (`de-AT`). Регион без языка нельзя. `de` покрывает всех немецкоязычных, `de-AT` только Австрию.
- `x-default`: куда отправлять тех, кто не подходит ни под одну версию (страница выбора страны или английская).
- Взаимность обязательна: если A ссылается на B, B должна ссылаться на A, иначе Google игнорирует пару. Это защита от того, что чужой сайт объявит твою страницу своей версией.
- Три способа: в `<head>`, в HTTP-заголовке `Link` (для PDF), в sitemap через `xhtml:link`. Для 7 стран и тысяч страниц sitemap удобнее, head раздувается.
- Это подсказка. hreflang не поднимает позиции, он выбирает, какую из версий показать.

Структура URL, trade-off:
- **Subfolder** `site.com/de/`: один домен, весь ссылочный вес общий, одна инфраструктура, один Search Console. Обычно лучший выбор для старта и для большинства.
- **Subdomain** `de.site.com`: Google считает ближе к отдельному сайту, вес делится частично. Полезно, когда страны живут на разных стеках или у разных команд.
- **ccTLD** `site.de`: самый сильный гео-сигнал и доверие локальных пользователей, но это отдельный домен: ссылочный вес с нуля, покупка и поддержка доменов, отдельное SEO на каждую страну. Дорого, оправдано для крупных брендов с локальными командами.
- Язык параметром `?lang=de` или по cookie / Accept-Language без смены URL: для SEO худшее, краулер увидит одну версию.

## Пример
Страница `/de-at/shoes` на сайте с тремя версиями:
```html
<link rel="alternate" hreflang="de-DE" href="https://site.com/de-de/shoes">
<link rel="alternate" hreflang="de-AT" href="https://site.com/de-at/shoes">
<link rel="alternate" hreflang="en" href="https://site.com/en/shoes">
<link rel="alternate" hreflang="x-default" href="https://site.com/en/shoes">
<link rel="canonical" href="https://site.com/de-at/shoes">
```
Ровно этот же набор должен стоять на `/de-de/shoes` и на `/en/shoes`. Canonical на каждой версии указывает на саму себя, не на «основную» английскую: иначе Google свернёт все версии в одну, и hreflang потеряет смысл.

В Next.js это `alternates.languages` в `generateMetadata`. Список версий генерировать из одного источника (конфиг локалей × существование страницы в локали), а не писать руками, иначе взаимность сломается на первом же товаре, которого нет в одной из стран.

## Подводные камни
- Ссылка на версию, которой нет (товар не продаётся в Австрии): hreflang ведёт на 404 или редирект, Google игнорирует. Генерировать только для реально существующих страниц.
- Автоматический редирект по IP или Accept-Language на «правильную» версию ломает всё: Googlebot ходит из US и видит только английскую. Предлагать баннером «похоже, вы в Австрии», а не редиректить.
- Одинаковый контент на `en-GB` и `en-US` это нормально, hreflang для этого и нужен, canonical между ними ставить не надо.
- Переводы через JS после загрузки без разных URL: для краулера одна страница.
- Красный флаг: «поставили hreflang, Google сам разберётся», без проверки взаимности. Интервьюер хочет: как генерируется, как проверяется (hreflang-валидаторы, Search Console по индексации каждой версии), и почему выбрали subfolder.

## Вопросы вдогонку
- **Что ставить в x-default?** Страницу выбора страны или глобальную английскую. Это не «версия для США», это fallback для тех, кому ничего не подошло.
- **hreflang и canonical конфликтуют?** Canonical должен совпадать с URL, на который ссылается hreflang для этой версии. Canonical на другой язык это ошибка.
- **`/de/` или `/de-at/` в URL?** Если контент различается по странам (цены, валюта, доставка), нужен регион. Если только язык, `/de/`.
- **Как Google определяет страну без ccTLD?** hreflang, локальный контент (валюта, адреса, телефоны), локальные ссылки, геотаргетинг по сигналам папки или поддомена.
