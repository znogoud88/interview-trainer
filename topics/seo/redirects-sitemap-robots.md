## Что это
**Коротко:** Техническая SEO-гигиена, которой владеет команда приложения. 301 это постоянный переезд, передаёт вес, 302 временный. Sitemap.xml это список канонических индексируемых страниц, и только их. robots.txt запрещает краулить, noindex запрещает индексировать, и это разные вещи: закрыл в robots и поставил noindex одновременно, значит noindex никто не прочитает. Миграция (редизайн, смена URL, новый фреймворк) без карты редиректов это классика потери позиций.

Редиректы:
- 301 / 308: постоянный, Google переносит сигналы на новый URL и заменяет его в индексе. 302 / 307: временный, старый URL остаётся в индексе. 307 и 308 ещё сохраняют метод запроса (POST не превращается в GET).
- Цепочки `http → https → www → /new/`: каждый прыжок это задержка для пользователя и для Googlebot, который после нескольких прыжков бросает. Схлопывать в один редирект на конечный URL.
- Редирект на сервере (nginx, middleware, `redirects` в next.config), не через JS или meta refresh: их краулер может не выполнить.
- Смена структуры URL = таблица «старый → новый» для каждого URL, включая картинки и PDF, которые тоже ранжируются.

Sitemap.xml:
- Внутрь: канонические, индексируемые, отдающие 200 страницы. Не внутрь: дубли, noindex, редиректы, 404, страницы за логином.
- Лимит 50 000 URL / 50 МБ на файл, поэтому sitemap index и split по типам (products, categories, articles): в Search Console видно, какой тип индексируется плохо.
- `lastmod` честный, по реальному изменению контента. Если всем страницам ставить «сегодня», Google перестаёт ему верить.
- Генерация из базы (`sitemap.ts` в Next.js), ссылка в robots.txt (`Sitemap: https://site.com/sitemap.xml`), отправка в Search Console.

robots.txt vs noindex:
- `Disallow: /admin/` в robots.txt: бот не скачает страницу. Но если на неё ссылаются, Google может показать URL в выдаче без сниппета. Это не способ спрятать.
- `<meta name="robots" content="noindex">` или заголовок `X-Robots-Tag: noindex`: бот краулит, читает запрет и не индексирует. Для non-HTML (PDF) только заголовок.
- Ловушка: страница с noindex, закрытая в robots.txt. Бот не заходит, noindex не читает, страница остаётся в индексе. Чтобы выкинуть из индекса, сначала открыть в robots.
- robots.txt для экономии crawl budget на технических URL (`?sort=`, внутренний поиск, корзина), noindex для страниц, которые должны открываться, но не ранжироваться.

## Пример
Миграция на новый фреймворк со сменой URL, порядок:
1. Выгрузить все URL со старого сайта: Search Console, sitemap, логи сервера, экспорт из аналитики по трафику. Не только те, что помнит команда.
2. Таблица редиректов 1:1 (`/catalog/shoes-123.html → /shoes/nike-air`), без «всё на главную»: массовый редирект на главную Google считает soft 404.
3. Сохранить структуру, title, h1, контент и внутренние ссылки, где можно. Редизайн не повод менять URL.
4. Staged rollout: сначала раздел, смотреть индексацию и позиции, потом остальное. Новый sitemap, старый не удалять сразу, чтобы бот быстрее нашёл редиректы.
5. После: Search Console каждый день первые недели. Всплеск 404 в Pages, падение кликов по шаблонам страниц, рост «Crawled, currently not indexed».

```js
// next.config.js: редирект на сервере, permanent = 308
async redirects() {
  return [{ source: '/catalog/:slug.html', destination: '/products/:slug', permanent: true }];
}
```

## Подводные камни
- Search Console, что смотреть регулярно: Pages (бывший Coverage: ошибки, excluded и причины), Performance (клики, показы, позиции по страницам и запросам), Core Web Vitals, Sitemaps (отправлено / в индексе).
- Как измерять эффект своей работы: до / после по шаблону страниц (все товарные, все категории), аннотации деплоев в аналитике, чтобы связать релиз и изменение трафика. Инженер, который видит связь «код → трафик», ценнее.
- 302 «временно, потом поменяем» живёт годами. Google давно трактует долгий 302 как постоянный, но лучше сразу ставить правильный код.
- Стейджинг, открытый наружу: закрывать basic auth или noindex, а не robots.txt (robots не мешает попасть в индекс по ссылкам).
- Красный флаг: «поставим Disallow, и страница выпадет из индекса» или «редиректы добавим после редизайна, если что-то упадёт». Интервьюер хочет: карта редиректов до релиза, мониторинг после.

## Вопросы вдогонку
- **Как быстро убрать страницу из индекса?** noindex при открытом robots, плюс Removals в Search Console для срочного. Удаление с 404/410 тоже работает, 410 чуть быстрее.
- **Что такое soft 404?** Страница «не найдено» с кодом 200. Google считает её мусором. Отдавать настоящий 404 с сервера (`notFound()` в Next.js).
- **Sitemap нужна маленькому сайту?** Не обязательна, если всё доступно по внутренним ссылкам, но она бесплатная и показывает в Search Console, что из отправленного не в индексе.
- **Сколько веса теряется на 301?** Google с 2016 говорит, что PageRank через 301/302 не теряется. Теряется время и сигналы, если цепочки или редирект на нерелевантную страницу.
