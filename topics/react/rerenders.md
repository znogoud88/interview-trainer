## Что это
**Коротко:** Ререндер это вызов функции компонента заново. Сам по себе он дёшев, проблема начинается, когда ререндерится много компонентов или один медленный. Процесс всегда один: сначала измерить в React DevTools Profiler, кто и почему рендерится, потом чинить причину: state слишком высоко, широкий context, нестабильные ссылки в props. Memo это последний шаг, а не первый.

Откуда берутся лишние ререндеры:
- **State слишком высоко.** Поле ввода хранит значение в state страницы, и каждое нажатие клавиши ререндерит всю страницу.
- **Широкий context.** Один `AppContext` с юзером, темой и корзиной: поменялась корзина, перерисовались все, кто читал тему.
- **Нестабильные ссылки.** Inline-объекты и функции в props ломают `React.memo` у детей.
- **Родитель отвечает за детей.** Если `Parent` рендерит `<ChildVerySlow />`, любой ререндер `Parent` тянет за собой медленного ребёнка, даже если ему ничего не поменяли. Медленный child тормозит и родителя.

Как чинить, по порядку:
1. **State colocation**: опустить state туда, где он реально нужен. Инпут хранит своё значение сам.
2. **Композиция**: всё, что меняется часто, вынести в отдельный компонент, а медленного ребёнка оставить снаружи или передать через `children`. Меняя композицию, уменьшаем количество ререндеров без memo.
3. **Разбить context** на несколько по частоте изменений, или вынести в стор с селекторами (zustand, jotai).
4. `React.memo` / `useMemo` точечно на то, что профайлер показал как тяжёлое.

## Пример
```jsx
// ❌ каждое нажатие в инпуте ререндерит Parent, а с ним и ChildVerySlow
function Parent() {
  const [text, setText] = useState("");
  return (
    <>
      <input value={text} onChange={e => setText(e.target.value)} />
      <ChildVerySlow />
    </>
  );
}

// ✅ state уехал в свой компонент, ChildVerySlow больше не трогается
function Parent() {
  return <><SearchInput /><ChildVerySlow /></>;
}
function SearchInput() {
  const [text, setText] = useState("");
  return <input value={text} onChange={e => setText(e.target.value)} />;
}
```

Если state всё-таки нужен в обёртке (layout с открытым сайдбаром), приём «children as props»: `<Layout><ChildVerySlow /></Layout>`. Элемент `<ChildVerySlow />` создан снаружи, при ререндере `Layout` его ссылка не меняется, и React его пропускает без всякого memo.

## Подводные камни
- Профайлер показывает «why did this render»: hooks changed, props changed, parent rendered. Без него починка это гадание.
- Не всякий ререндер нужно убирать: если он занимает 0.2 мс, оптимизация стоит дороже проблемы. Чинить то, что человек замечает.
- Context не умеет частичную подписку: читаешь `useContext`, ререндеришься при любом изменении value. Если value это объект, который пересоздаётся в провайдере каждый рендер, страдают все потребители. `useMemo` на value провайдера обязателен.
- Красный флаг: «обернул всё в memo» или «перенёс всё в Redux». Правильный ответ начинается со слова «профайлер».

## Вопросы вдогонку
- **Что видно в Profiler?** Flamegraph по коммитам, время каждого компонента, причина рендера, фильтр «только те, что рендерились». Калибруешь композицию по этому фидбеку.
- **Чем state colocation лучше memo?** Убирает причину, а не симптом: меньше кода, нечему сломаться при добавлении нового prop.
- **Как убрать ререндеры от контекста?** Разбить на несколько контекстов, `useMemo` на value, или стор с селекторами (`useStore(s => s.cart)`).
