## Что это
**Коротко:** `useMemo` кэширует результат вычисления между рендерами, `useCallback` кэширует ссылку на функцию, `React.memo` оборачивает компонент и пропускает его ререндер, если props не изменились по `Object.is`. Все три работают вместе: `React.memo` бесполезен, если в props прилетает новая функция или объект каждый рендер. Применять точечно, после профайлера, а не «на всякий случай».

Как это связано:
- По умолчанию при ререндере родителя ререндерятся все дети, независимо от props. `React.memo` ставит проверку «а props вообще поменялись?».
- Props сравниваются поверхностно, по ссылкам. `onClick={() => ...}` и `style={{...}}` это новая ссылка каждый раз, и memo не сработает.
- Отсюда `useCallback` для функций и `useMemo` для объектов и массивов, которые идут в memo-компонент или в зависимости хуков.
- `useMemo` для дорогих вычислений: фильтрация и сортировка 10 000 строк на каждый ввод в поле.

React Compiler (стабильная 1.0 с октября 2025): babel-плагин, который сам мемоизирует компоненты, хуки и значения на этапе сборки. Код пишешь без `useMemo`/`useCallback`, компилятор расставляет их за тебя, при условии что код соблюдает правила React (чистый рендер, без мутаций props и state). Работает с React 17+, лучше всего с 19. ESLint-плагин компилятора показывает, где он не смог мемоизировать и почему.

## Пример
```jsx
// ❌ memo не поможет: onSelect это новая функция каждый рендер родителя
const Row = React.memo(function Row({ item, onSelect }) { ... });

function List({ items }) {
  const [selected, setSelected] = useState(null);
  return items.map(i => <Row key={i.id} item={i} onSelect={() => setSelected(i.id)} />);
}

// ✅ стабильная ссылка, Row ререндерится только когда item поменялся
function List({ items }) {
  const [selected, setSelected] = useState(null);
  const onSelect = useCallback((id) => setSelected(id), []);
  return items.map(i => <Row key={i.id} item={i} onSelect={onSelect} />);
}
```

## Подводные камни
- Мемоизация не бесплатна: сравнение props, хранение предыдущих значений, память. На дешёвом компоненте `React.memo` может стоить дороже, чем ререндер.
- `useMemo` это оптимизация, а не гарантия: React может сбросить кэш (документация прямо об этом говорит). Не прячь туда логику, от которой зависит корректность.
- Цепочка должна быть целой: один нестабильный prop, и вся мемоизация ниже зря. Проверяй в DevTools «why did this render».
- Сначала посмотреть, нельзя ли решить композицией: state colocation, вынести медленного ребёнка в `children`. Часто это убирает проблему без единого memo.
- Красный флаг: «я оборачиваю всё в useCallback, чтобы было быстрее». Ответ сеньора: измерил, нашёл, починил точечно; в новом проекте включил Compiler.

## Вопросы вдогонку
- **Почему React.memo не сработал, хотя props те же?** Какой-то prop это новый объект, функция или `children` (JSX создаётся заново). Сравнение по ссылке.
- **Когда useMemo обязателен, а не оптимизация?** Когда значение идёт в зависимости `useEffect` или в props memo-компонента: без стабильной ссылки эффект будет перезапускаться каждый рендер.
- **Что делает React Compiler и что ломает?** Авто-мемоизация на сборке. Компоненты, которые нарушают правила (мутируют props или state, читают ref в рендере), он пропускает, не мемоизирует.
- **Нужен ли useCallback, если включён Compiler?** Обычно нет, компилятор делает это сам. Руками остаётся только там, где он отказался.
