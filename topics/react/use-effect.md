## Что это
**Коротко:** `useEffect` это способ синхронизировать компонент с внешним миром: подписки, таймеры, ручная работа с DOM, интеграция с не-React библиотекой. Это не «сделать что-то после рендера» и не «отреагировать на изменение данных». Если эффект нужен, чтобы посчитать значение из state или ответить на клик, это неправильный инструмент.

Когда нужен:
- Подписка на что-то снаружи (WebSocket, `window.addEventListener`, `ResizeObserver`) и отписка в cleanup.
- Таймеры, `setInterval`, с очисткой.
- Управление не-React виджетом (карта, чарт) через ref.
- Fetch данных, если нет React Query / loader роутера / фреймворка, которые делают это лучше.

Когда не нужен:
- Производные данные: `fullName` из `first` и `last`. Просто вычисли в рендере, при необходимости `useMemo`.
- Реакция на действие пользователя: отправка формы, аналитика по клику. Это обработчик события, а не эффект на изменение state.
- Сброс state при смене props: лучше `key` на компоненте.
- «Синхронизация» одного state с другим через эффект: лишний рендер и источник рассинхрона.

Механика: эффект запускается после коммита, cleanup вызывается перед следующим запуском эффекта и при unmount. Массив зависимостей говорит, когда перезапускать. В StrictMode в dev эффекты монтируются дважды, чтобы проверить, что cleanup правильный.

## Пример
```jsx
// ❌ гонка: быстро меняем query, старый ответ приходит позже нового и перетирает его
useEffect(() => {
  fetch(`/api/search?q=${query}`).then(r => r.json()).then(setResults);
}, [query]);

// ✅ AbortController: отменяем предыдущий запрос в cleanup
useEffect(() => {
  const ctrl = new AbortController();
  fetch(`/api/search?q=${query}`, { signal: ctrl.signal })
    .then(r => r.json())
    .then(setResults)
    .catch(e => { if (e.name !== "AbortError") setError(e); });
  return () => ctrl.abort();
}, [query]);
```

Если отменить запрос нельзя, тот же эффект с флагом `let ignore = false`, в cleanup `ignore = true`, и `if (!ignore) setResults(...)`.

## Подводные камни
- **Stale closure**: эффект замкнул значения из того рендера, в котором создан. `setInterval(() => setCount(count + 1), 1000)` с `[]` всегда прибавит к нулю. Фикс: функциональный апдейт `setCount(c => c + 1)` или честные зависимости.
- **Забытые зависимости**: линтер `react-hooks/exhaustive-deps` не враг. Если хочется его выключить, скорее всего эффект вообще не нужен, или нужен `useEffectEvent` (стабилен с React 19.2) для чтения свежих значений без перезапуска эффекта.
- **Бесконечный цикл**: в зависимостях объект или массив, который создаётся заново каждый рендер (`options = { page }`). Эффект ставит state, рендер, новая ссылка, эффект снова. Фикс: примитивы в зависимостях, `useMemo`, или вынести объект наружу компонента.
- **Гонки запросов**: без отмены или флага ответы приходят в случайном порядке. Это не теория, это «поиск показывает результаты для предыдущего слова».
- Красный флаг: `useEffect` для копирования props в state и для вычисления производных данных. Интервьюер в R3 именно это и проверяет.

## Вопросы вдогонку
- **Чем useLayoutEffect отличается?** Запускается синхронно до того, как браузер нарисует кадр. Для измерений DOM и позиционирования, чтобы не было мигания. В остальном `useEffect`.
- **Почему эффект срабатывает дважды в dev?** StrictMode симулирует unmount/mount, чтобы поймать эффекты без cleanup. В проде один раз.
- **Как сбросить state при смене id без эффекта?** `<UserForm key={userId} />`: React размонтирует и смонтирует заново.
- **Что делать с fetch в эффекте в большом проекте?** React Query или loader роутера: кэш, дедупликация, отмена, retry из коробки.
