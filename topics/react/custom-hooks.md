## Что это
**Коротко:** Кастомный хук это обычная функция с именем `useXxx`, которая внутри вызывает другие хуки. Это способ вынести из компонента переиспользуемую логику с состоянием: `useDebounce`, `usePagination`, `useLocalStorage`, `useMediaQuery`. Хук не делит state между компонентами: каждый вызов получает свой независимый state, делится только логика.

Правила хуков и почему они есть:
- Вызывать только на верхнем уровне компонента или другого хука: не в условиях, циклах, после `return`, не в обычных функциях и обработчиках.
- Причина: React хранит state хуков в связном списке по порядку вызова, а не по имени. Первый `useState` это слот 0, второй слот 1. Если на одном рендере хук пропустить, все следующие прочитают чужие слоты.
- Имя с `use` это не магия, а конвенция, по которой линтер (`eslint-plugin-react-hooks`) понимает, что внутри хуки, и проверяет правила.
- Хук в хуке вызывать можно, это и есть композиция.

Что делает хук хорошим:
- Делает одну вещь и возвращает понятный контракт: значение, или `[value, setValue]`, или объект с полями.
- Чистит за собой: подписка в `useEffect` с cleanup.
- Принимает примитивы или стабильные ссылки, иначе внутри эффекты будут перезапускаться.
- Не прячет то, что компоненту нужно для рендера (loading/error).

## Пример
```jsx
// useDebounce: отдаёт значение с задержкой, пока пользователь не перестанет печатать
function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);   // новое значение пришло раньше, старый таймер отменяем
  }, [value, delay]);
  return debounced;
}

function Search() {
  const [q, setQ] = useState("");
  const debouncedQ = useDebounce(q);
  const { data } = useQuery({ queryKey: ["search", debouncedQ], queryFn: ... });
  ...
}
```

Хуки из практики, которые стоит иметь наготове для вопроса «расскажи про свой»: `usePagination` (page, pageSize, next/prev, total), `useClickOutside(ref, handler)`, `useIsOnline`, `usePrevious`.

## Подводные камни
- Хук нужен не везде: если логика без state и без эффектов, это обычная функция, и назвать её `useFormat` только запутает.
- Возвращать объект, который пересоздаётся каждый рендер, и класть его в зависимости в компоненте = лишние эффекты. Мемоизировать или возвращать примитивы.
- «Хук как глобальный state»: два компонента вызвали `useCart()` и ожидают общую корзину. Не будет, state у каждого свой. Для общего нужен context или стор.
- Условный вызов хука «потому что он нужен только если залогинен» ломает порядок. Условие внутри хука или вынести в отдельный компонент.
- Красный флаг на собесе: нет живого примера. Ответ «писал useDebounce и usePagination, вот зачем и как» это то, что проверяет R10.

## Вопросы вдогонку
- **Почему нельзя вызвать хук в условии?** Порядок вызова определяет, какой state принадлежит какому хуку. Условие меняет порядок между рендерами.
- **Разделяют ли два компонента state одного хука?** Нет. Хук переиспользует логику, не данные. Общие данные через context или стор.
- **Чем кастомный хук лучше HOC или render props?** Нет лишних обёрток в дереве, понятно откуда что приходит, типизируется проще.
- **Как тестировать хук?** `renderHook` из Testing Library, `act` для обновлений. Или тестировать через компонент, который его использует.
