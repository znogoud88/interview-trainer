## Что это
**Коротко:** React нужен, чтобы описывать интерфейс декларативно: ты говоришь, ЧТО показать при таком-то состоянии, а не КАК руками менять DOM. Props это данные, которые компонент получает снаружи и не меняет. State это данные, которые компонент хранит сам и меняет через `useState`. Изменение любого из них вызывает ререндер.

Какую проблему решает:
- На vanilla JS интерфейс это куча `querySelector` и `innerHTML`, и при каждом изменении данных надо помнить, какие куски DOM обновить. На 10 элементах ок, на большом приложении это рассинхрон и баги «забыл обновить счётчик в шапке».
- React: `UI = f(state)`. Меняешь state, React сам пересчитывает, что должно быть на экране, и применяет минимальные правки в DOM (reconciliation, Virtual DOM).
- Компоненты: UI собирается из переиспользуемых кусков с понятным контрактом (props).

Props vs state:
- Props приходят от родителя, read-only. Хочешь изменить, зови колбэк из props (`onChange`): меняет тот, кто владеет данными.
- State живёт внутри компонента. Меняется только через setter, прямое `state.x = 1` React не увидит.
- Setter не меняет значение в той же строке: новое значение будет в следующем рендере.

## Пример
```jsx
// ❌ императивно: сами следим за DOM
let count = 0;
button.addEventListener("click", () => {
  count++;
  counterEl.textContent = count;   // а второй элемент, где тоже показан count, забыли
});

// ✅ декларативно: описали, что показать, React обновляет DOM сам
function Counter({ label }) {            // label это prop, снаружи
  const [count, setCount] = useState(0); // count это state, внутри
  return <button onClick={() => setCount(c => c + 1)}>{label}: {count}</button>;
}
```

## Подводные камни
- Virtual DOM это не «быстрее, чем DOM». Это способ не трогать DOM руками и обновлять только то, что изменилось. Прямые правки DOM всегда быстрее, но их невозможно поддерживать.
- Мутировать state (`arr.push(x); setArr(arr)`) не работает: ссылка та же, React считает, что ничего не изменилось. Нужен новый объект или массив.
- Копировать prop в state (`useState(props.value)`) это классический баг: копия не обновится, когда поменяется prop. Либо читай prop напрямую, либо сбрасывай через `key`.
- Красный флаг на собесе: «props и state это одно и то же, только state можно менять». Нужно сказать про владение: кто владеет данными, тот и меняет.

## Вопросы вдогонку
- **Почему setState не меняет значение сразу?** Обновления батчатся и применяются в следующем рендере, в текущем замыкании старое значение. Для цепочки используй `setCount(c => c + 1)`.
- **Что такое one-way data flow?** Данные идут вниз через props, события идут вверх через колбэки. Ребёнок не меняет чужой state напрямую.
- **Что такое Virtual DOM?** Лёгкое дерево объектов, описывающее UI. React сравнивает новое с предыдущим и применяет к реальному DOM только разницу.
- **Что такое JSX?** Синтаксический сахар над вызовами функций (`createElement` / `jsx`), компилируется на сборке, в браузер не попадает.
