## Что это
**Коротко:** Hydration это когда браузер получил готовый HTML с сервера и React «оживляет» его: строит своё дерево, сравнивает с тем, что уже в DOM, и навешивает обработчики событий, не пересоздавая разметку. Hydration error это когда дерево, которое React отрендерил на клиенте, не совпало с HTML от сервера. React ругается в консоль, а в худшем случае выбрасывает серверную разметку и рендерит всё заново на клиенте.

Почему не совпадает: клиентские компоненты рендерятся дважды, сначала на сервере в HTML, потом в браузере для hydration. Любой код, который даёт разный результат в двух средах, ломает совпадение:
- Время и рандом: `Date.now()`, `new Date().toLocaleString()`, `Math.random()`. На сервере одно значение, у клиента другое.
- Браузерные API в рендере: `window.innerWidth`, `localStorage.getItem("theme")`, `navigator.language`. На сервере их нет, значит рендер идёт по другой ветке.
- Локали и таймзоны: сервер в UTC, пользователь в Москве, дата отформатировалась по-разному.
- Невалидный HTML: `<div>` внутри `<p>`, `<a>` внутри `<a>`, `<tr>` без `<tbody>`. Браузер молча чинит разметку, React видит уже «починенный» DOM и не узнаёт его.
- Расширения браузера, которые дописывают атрибуты и элементы в `<body>` (переводчики, менеджеры паролей).

## Пример
```tsx
// ❌ сервер отрендерил "десктоп", клиент на телефоне говорит "мобилка": mismatch
function Nav() {
  const isMobile = typeof window !== "undefined" && window.innerWidth < 768;
  return isMobile ? <MobileNav /> : <DesktopNav />;
}

// ✅ первый рендер на клиенте совпадает с серверным, переключение после mount
function Nav() {
  const [isMobile, setIsMobile] = useState(false);
  useEffect(() => { setIsMobile(window.innerWidth < 768); }, []);
  return isMobile ? <MobileNav /> : <DesktopNav />;
}

// ✅ для таймстемпов, где разница ожидаема: подавить предупреждение точечно
<time suppressHydrationWarning>{new Date().toLocaleTimeString()}</time>

// ✅ компонент, которому сервер вообще не нужен (карта, график, редактор)
const Chart = dynamic(() => import("./chart"), { ssr: false }); // только в client component
```

## Подводные камни
- `typeof window !== "undefined"` в рендере не фикс, а источник бага: ветка просто другая на сервере и на клиенте. Фикс это одинаковый первый рендер, а клиентские отличия после `useEffect`.
- Паттерн `useEffect` + state даёт лишний рендер и мигание (сначала дефолт, потом настоящее). Для темы или ширины экрана иногда честнее CSS media query, а не JS.
- `suppressHydrationWarning` работает на один элемент и только на текст и атрибуты, не на структуру. Вешать его на `<body>` «чтобы не ругалось» это заметание под ковёр.
- Со стриминга и Suspense hydration идёт по частям: сломанный кусок внутри Suspense boundary React перерендерит на клиенте сам, остальная страница останется серверной. Поэтому ошибка не всегда «вся страница белая», но она всё равно стоит CPU и времени.
- Next 15 показывает diff серверного и клиентского HTML прямо в оверлее ошибки, искать стало проще. Красный флаг на собесе: «просто отключил SSR для всей страницы».

## Вопросы вдогонку
- **Чем hydration отличается от обычного рендера на клиенте?** Рендер создаёт DOM с нуля. Hydration берёт существующий DOM и только привязывает к нему React-дерево и обработчики. Быстрее, но требует совпадения.
- **Server Components тоже гидрируются?** Нет. Они не имеют клиентского кода, их результат это просто разметка. Гидрируются только компоненты с `"use client"`.
- **Как прочитать localStorage без mismatch?** `useSyncExternalStore` с `getServerSnapshot`, который возвращает дефолт, или `useEffect` после mount. Или отрендерить значение через cookie на сервере, тогда оно известно заранее.
- **Что такое selective hydration?** React 18 гидрирует Suspense-куски независимо и в первую очередь тот, с которым пользователь взаимодействует, не ждёт весь бандл.
