## Что это
**Коротко:** N+1 это когда код делает один запрос за списком, а потом по отдельному запросу на каждый элемент списка. 100 заказов = 1 + 100 запросов. Каждый запрос быстрый, но их сотни, и страница тормозит, а база нагружена.

Чаще всего появляется с ORM: пишешь `order.customer`, и ORM молча ходит в базу за каждым клиентом. В коде это выглядит невинно, потому что цикл и запросы спрятаны.

Чем лечить:
- **Eager loading**: сказать ORM заранее подтянуть связь одним запросом (`include` в Prisma, `with` в Laravel, `select_related` в Django, `relations` в TypeORM).
- **JOIN** руками: один SQL, который отдаёт заказы вместе с клиентами.
- **Батчинг**: собрать id, сделать один `WHERE id IN (...)`. Так работает DataLoader в GraphQL.

## Пример
```js
// ❌ N+1: один запрос за заказами, потом по запросу на каждого клиента
const orders = await db.order.findMany();            // SELECT * FROM orders
for (const o of orders) {
  o.customer = await db.customer.findUnique({ where: { id: o.customerId } }); // ×100
}

// ✅ eager loading: два запроса или один JOIN, не зависит от количества заказов
const orders = await db.order.findMany({ include: { customer: true } });
```

На фронте та же история: список постов, и на каждый пост отдельный `GET /authors/:id`. Лечится эндпоинтом, который отдаёт данные под экран, или BFF.

## Подводные камни
- Как заметить: логи запросов, debug toolbar, количество запросов растёт вместе с размером списка. Локально на 5 записях не видно, в проде на 5000 ложится база.
- Eager loading везде это другая крайность: тянешь половину базы ради одного поля. Грузи только то, что нужно экрану.
- GraphQL делает N+1 особенно легко: каждый резолвер поля ходит в базу сам по себе. Поэтому там DataLoader это must-have.
- Красный флаг на собесе: «ORM сам оптимизирует». Не оптимизирует, пока не попросишь.

## Вопросы вдогонку
- **Как найти N+1 в проде?** Мониторинг количества запросов на один HTTP-запрос, APM (Sentry, Datadog показывают «101 query»), логи ORM.
- **JOIN или два запроса?** JOIN это один round-trip, но дублирует данные родителя в каждой строке. Два запроса (список + IN) проще и часто не хуже. Зависит от размеров.
- **Как это связано с GraphQL?** Резолверы вызываются по полю на каждый объект, N+1 там по умолчанию. DataLoader батчит и кэширует в рамках одного запроса.
