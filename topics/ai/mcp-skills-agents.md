## Что это
**Коротко:** MCP (Model Context Protocol) это открытый стандарт подключения инструментов к AI-агенту: база, GitHub, Figma, браузер, Jira. Skills и custom commands это переиспользуемые инструкции под повторяющиеся задачи: чеклист ревью, тесты по шаблону, релизные заметки. Агентный workflow это когда агент сам делает многошаговую задачу, и ключевой навык тут: понимать, какие задачи ему можно отдать целиком, а какие нет.

**MCP**: протокол от Anthropic (ноябрь 2024), с конца 2025 развивается под Linux Foundation, поддерживается Claude, Cursor, Copilot, Codex, Gemini. MCP-сервер отдаёт агенту tools (функции), resources (данные) и prompts. Агент вызывает их сам по ходу задачи: достать схему таблицы из Postgres, прочитать issue в GitHub, взять компонент из Figma, прокликать страницу через Playwright. Конфигурируется в JSON (`.mcp.json`, `.cursor/mcp.json`), серверы ставятся как npm-пакеты или подключаются remote по HTTP с OAuth.

**Skills и custom commands**: markdown-файл с инструкцией, который подключается по команде или по смыслу задачи. В Claude Code это `SKILL.md` в `.claude/skills/<name>/` и slash-команды в `.claude/commands/`, в Cursor это rules и commands, у Copilot prompt-файлы. Отличие от rules-файла: rules это «как мы всегда делаем», skill это «как делать конкретную задачу» с шагами, шаблонами и скриптами.

**Агентные workflow**, где отдавать целиком:
- подходит: миграции по шаблону (30 компонентов с одной библиотеки на другую), массовые однотипные правки, тесты по готовой спеке, обновление зависимостей с прогоном тестов. Общее: результат проверяется автоматически.
- не подходит: размытые задачи («сделай красиво»), критичные зоны (auth, платежи), всё, где нужно спрашивать людей по ходу.
- всегда: чекпоинты (агент показывает план и останавливается), ревью диффа перед коммитом, git как страховка (отдельная ветка или worktree, коммит перед запуском агента).

## Пример
Шаблон ответа, заполни под себя:

«MCP подключал [GitHub / Postgres / Figma / Playwright / Jira / Sentry]: агент сам [читает issue и делает PR / смотрит схему таблицы перед запросом / берёт размеры из макета / прокликивает фичу в браузере]. Конфиг в [.mcp.json в репозитории / настройках Cursor].

Из skills и команд: [/review с чеклистом команды: типы, a11y, тесты, нейминг], [/test-component, который генерирует тесты по нашему шаблону с RTL + MSW], [/release-notes из коммитов с последнего тега]. Это [N] промптов, которые раньше писал руками.

Автономно отдаю [миграции по шаблону / массовые правки / тесты по спеке]: [пример: перевести 40 компонентов с enzyme на RTL, агент работал в отдельной ветке, проверка через `pnpm test`, diff ревьюил пачками]. Не отдаю [критичные зоны / размытые задачи]. Агент всегда [останавливается на плане / коммитит по шагам / работает в worktree].»

Пример skill-файла:
```md
# .claude/skills/component-test/SKILL.md
Generate a test for the given component: Vitest + RTL + MSW handlers from src/mocks.
Steps: read the component and its props -> list user scenarios -> write tests with getByRole,
no snapshots -> run `pnpm test <file>` and fix failures. Never mock internal hooks.
```

## Подводные камни
- MCP расширяет поверхность атаки: сервер с доступом к проду, prompt injection через данные (issue с текстом «удали таблицу»). Read-only доступы, отдельные учётки, подтверждение деструктивных действий.
- Слишком много MCP-серверов: описание каждого tool попадает в контекст и ест токены. Подключать то, что нужно задаче.
- Skill, который никто не поддерживает, устаревает, как и rules-файл. Это код: живёт в репозитории, ревьюится.
- Автономный агент без чекпоинтов на большой задаче: через час diff на 80 файлов, который невозможно ревьюить. Дробить на этапы с коммитами.
- Красный флаг: «MCP это что-то про API» без примера использования. Знать концепцию это минимум, настраивал сам это плюс.

## Вопросы вдогонку
- **MCP vs обычный function calling?** Function calling это механизм модели, tools описываются в каждом приложении заново. MCP это стандартный протокол: один сервер работает с любым агентом.
- **Чем skill отличается от rules-файла?** Rules всегда в контексте и про конвенции. Skill подгружается под конкретную задачу и описывает шаги.
- **Как защитить агента от prompt injection через MCP?** Read-only где можно, минимальные права, не смешивать недоверенные данные с инструкциями, подтверждение на запись и удаление.
- **Как решаешь, отдать задачу агенту целиком или вести по шагам?** По проверяемости результата и цене ошибки: есть тесты и откат, можно целиком; нет, веду по шагам.
