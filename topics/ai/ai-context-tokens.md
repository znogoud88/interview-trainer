## Что это
**Коротко:** Качество вывода равно качеству ТЗ: промпт это мини-спека с acceptance criteria, edge cases и явным «что не трогать». Конвенции проекта живут в rules-файле, а не повторяются в каждом чате. Контекст точечный: конкретные файлы, не весь репозиторий. И модель платная за токены: длинные чаты и огромные файлы в контексте это деньги и ухудшение качества.

Промпт как спека:
- что сделать и где: конкретные файлы, существующий паттерн («как в `features/catalog/api.ts`»)
- acceptance criteria и edge cases
- ограничения: «не трогать схему БД», «не добавлять зависимости», «публичный API не менять»
- как проверить: «прогони `pnpm test --filter ui`»

Rules-файлы: `CLAUDE.md` (Claude Code), `.cursor/rules/*.mdc` (Cursor, можно по glob на часть проекта), `.github/copilot-instructions.md` (Copilot), `AGENTS.md` как общий формат, который читают Codex, Cursor и другие. Внутри: стек и версии, команды сборки и тестов, конвенции (именование, структура папок, как делаем формы и запросы), запреты, карта проекта. Короткий, актуальный, лежит в репозитории, меняется через PR.

Что жрёт токены впустую:
- огромные файлы и целые папки в контексте «на всякий случай»
- длинные чаты: история отправляется заново на каждом шаге, чат на 200 сообщений в разы дороже свежего
- повторные объяснения конвенций вместо rules-файла
- агент, который читает по пять файлов, чтобы найти то, что можно было указать путём

Оптимизация: новый чат на новую задачу, компакт при длинной сессии, точечный контекст через `@file`, дешёвая модель для простых правок (Haiku, Sonnet) и сильная для архитектуры и сложного дебага (Opus). Prompt caching в агентах включён по умолчанию, но работает только для стабильного префикса: rules-файл в начале кешируется, хаотичная история нет.

## Пример
Шаблон ответа, заполни под себя:

«Конвенции держу в [CLAUDE.md / .cursor/rules]: [стек, команды, правило «формы через react-hook-form + zod», запрет на новые Redux-слайсы]. Задачу ставлю как мини-спеку: [пример: «добавь фильтр по статусу в список заказов, как сделан фильтр по дате в `OrdersFilters.tsx`, статус в URL через nuqs, не трогай API-клиент, тесты в `orders.test.tsx` должны пройти»].

На задачу новый чат, в контекст кидаю [2-4 файла], не папку. Длинную сессию [компактю / начинаю заново] после [крупного этапа]. Простые правки на [Sonnet / Haiku / auto-режим], архитектуру и сложный дебаг на [Opus / GPT-5].

Расход: [Claude Pro или Max $20-200 + Cursor Pro $20] в месяц, или через API примерно [N] млн токенов, [$X]. Пики на [миграциях / больших рефакторингах].»

Кусок rules-файла:
```md
# Stack: Next.js 15, React 19, TS strict, pnpm, Vitest + RTL, TanStack Query
# Commands: pnpm test, pnpm lint, pnpm typecheck (run before finishing)
- Server data only via TanStack Query hooks in features/*/api. No fetch in components.
- Forms: react-hook-form + zod schema next to the form.
- Do not edit packages/api-client/generated/* (generated from OpenAPI).
```

## Подводные камни
- Rules-файл на 500 строк не читается внимательнее, чем на 50: он просто ест контекст. Главное наверх, детали в scoped-правила или по ссылкам.
- Устаревший rules-файл хуже отсутствующего: агент уверенно делает «как написано», а написано про прошлый стек.
- «Скормил весь репозиторий» не делает ответ лучше: модель теряет фокус, растёт цена и шанс галлюцинаций.
- Замешательство на вопросе «сколько тратишь» читается как «не пользуешься всерьёз». Порядок цифр достаточен.
- Красный флаг: «просто пишу, что хочу, и он делает». Без спеки первая попытка редко правильная.

## Вопросы вдогонку
- **Что кладёшь в CLAUDE.md, а что нет?** Кладу: стек, команды, конвенции, запреты, карту проекта. Не кладу: документацию библиотек, историю решений, то, что модель и так знает.
- **Когда начинать новый чат?** На каждую новую задачу и когда агент начинает забывать ранние договорённости.
- **Как выбираешь между дешёвой и дорогой моделью?** По цене ошибки: правка текста и простой рефакторинг на дешёвой, архитектура, сложный дебаг и security-зоны на сильной.
- **Что такое prompt caching и как его не ломать?** Повторяющийся префикс (system, rules, описания tools) тарифицируется дешевле. Ломается, если менять начало контекста на каждом шаге.
