## Что это
**Коротко:** В облаке неожиданно жгут деньги не серверы, а egress-трафик (данные наружу платные, внутрь бесплатно), NAT gateway, логи гигабайтами, межзонный трафик, забытые ресурсы и копящиеся снапшоты. Kubernetes это оркестрация контейнеров: реплики, самолечение, скейлинг, но большинству проектов хватит проще: Cloud Run, ECS, Fly.io, PaaS. IaC (Terraform) нужен, потому что кликнутое в консоли никто не помнит и не воспроизведёт.

**Что жрёт деньги** (кто видел счёт, тот знает):
- **Egress**: отдать данные из облака в интернет или в другой регион стоит денег, принять бесплатно. Картинки без CDN, бэкапы в другое облако, API с большими ответами.
- **NAT gateway**: приватная подсеть ходит в интернет через NAT, и каждый гигабайт плюс часы работы платные. Классика: Lambda в VPC качает из S3 через NAT вместо VPC endpoint.
- **Логи**: ingestion и хранение в CloudWatch или Datadog. Debug-логи в проде на каждый запрос это тысячи долларов.
- **Межзонный трафик**: реплики в разных AZ переговариваются, и это тоже платно.
- **Забытое**: неприкреплённые диски, старые снапшоты, Elastic IP без инстанса, тестовый кластер «на недельку», load balancer без бэкендов.

**Kubernetes**: описываешь желаемое состояние (3 реплики этого образа, вот ресурсы, вот health check), кластер его поддерживает: упал под, поднял новый, нагрузка выросла, добавил реплик. Цена: своя сложность, YAML, сеть, ingress, секреты, апгрейды кластера, нужен человек, который это понимает. Оправдан, когда десятки сервисов, несколько команд, особые требования к сети или уже есть платформенная команда. Один фронт и пара сервисов на k8s это overengineering.

**Terraform / IaC**: инфраструктура в коде: версионируется, ревьюится в PR, воспроизводится в новом регионе или окружении. `terraform plan` показывает, что изменится, `apply` применяет, state-файл хранит, что уже создано (хранить удалённо с блокировкой, не в репо). Кликнул в консоли значит никто не знает, что и почему, и окружения расходятся.

## Пример
Счёт вырос вдвое за месяц, ничего не деплоили. Разбор по Cost Explorer: 60% прироста это NAT gateway data processing. Причина: новый cron в Lambda внутри VPC каждые 5 минут качает отчёт из S3 через NAT. Фикс: S3 gateway endpoint (бесплатный), трафик пошёл мимо NAT. Второе место: CloudWatch Logs, кто-то включил debug-уровень в проде. Третье: три снапшота по 500 ГБ от «временного» теста полгода назад.

## Подводные камни
- Нет бюджета и алерта на расходы: о проблеме узнаёшь из счёта через месяц. Budget alert это первое, что ставят.
- Теги на ресурсы (team, env, project): без них нельзя понять, кто тратит. Tagging policy в IaC.
- Terraform без удалённого state и lock: два человека применили параллельно, state сломан. Или state в репо с секретами внутри.
- «Нам нужен Kubernetes, потому что так у всех» это буззворд. Интервьюер на senior ждёт трезвости: когда k8s оправдан и чем заменить.
- Autoscaling без верхней границы: DDoS или баг с ретраями, и облако честно масштабируется на тысячи долларов.

## Вопросы вдогонку
- **Чем заменить Kubernetes для небольшого проекта?** Cloud Run, ECS Fargate, App Runner, Fly.io, Railway, Vercel для фронта. Отдаёшь контейнер, остальное делает платформа.
- **Что такое Terraform state?** Файл, где Terraform помнит соответствие кода и реальных ресурсов. Хранится в S3 с lock или в Terraform Cloud.
- **Как уменьшить egress?** CDN перед статикой и картинками, сжатие ответов, не гонять данные между регионами, VPC endpoints для S3.
- **Что такое drift?** Реальная инфраструктура разошлась с кодом, потому что кто-то поправил руками. `terraform plan` показывает разницу.
