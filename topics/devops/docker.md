## Что это
**Коротко:** Docker упаковывает приложение вместе с окружением (runtime, зависимости, системные библиотеки), чтобы оно работало одинаково на ноутбуке, в CI и в проде. Image это слепок, неизменяемый шаблон из слоёв. Container это запущенный экземпляр image. «У меня работает» перестаёт быть аргументом.

**Dockerfile** это рецепт image. Каждая инструкция (`FROM`, `COPY`, `RUN`) создаёт слой, слои кэшируются. Порядок важен: если слой изменился, всё ниже него пересобирается. Поэтому `package.json` копируют и ставят зависимости отдельно, до копирования кода: код меняется каждый коммит, зависимости редко, и `npm ci` не повторяется каждый раз.

**Multi-stage build**: первая стадия собирает (нужны dev-зависимости, TypeScript, бандлер), финальная стадия берёт из неё только результат. В прод-образ не попадают devDependencies, исходники и кэши. Меньше размер, меньше поверхность атаки, быстрее деплой.

**Image на 2 ГБ, как похудеть**: multi-stage; база `node:20-alpine` или `-slim` вместо полного `node:20`; `.dockerignore` с `node_modules`, `.git`, `dist`; только prod-зависимости в финальном слое (`npm ci --omit=dev`); для статического фронта вообще nginx с папкой `dist`.

**docker compose**: несколько контейнеров одной командой: приложение, Postgres, Redis, mock-сервер. `docker compose up`, и у всей команды одинаковое окружение. Повседневный инструмент разработчика, не только DevOps.

## Пример
```dockerfile
# ❌ один стейдж, всё подряд: dev-зависимости, исходники, кэши, 2 ГБ
FROM node:20
COPY . .
RUN npm install && npm run build
CMD ["node", "dist/server.js"]

# ✅ кэш слоёв + multi-stage
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci                      # кэшируется, пока package*.json не менялся
COPY . .
RUN npm run build

FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY --from=build /app/dist ./dist
CMD ["node", "dist/server.js"]
```

## Подводные камни
- `COPY . .` до `npm ci`: любая правка кода инвалидирует кэш, и зависимости ставятся заново. Детектор на собесе: кто ждал пересборки, тот выучил.
- Без `.dockerignore` локальные `node_modules` летят в контекст сборки: долго, и могут перебить бинарники, собранные под другую ОС.
- Alpine использует musl вместо glibc: некоторые нативные модули (sharp, старые бинарники) ломаются. Тогда `-slim`.
- Container это процесс: завершился главный процесс, умер контейнер. Данные внутри не переживают пересоздание, для БД нужны volumes.
- Один image на все окружения, конфиг через env снаружи. Запечь `API_URL` в образ значит пересобирать под каждый стенд.

## Вопросы вдогонку
- **Чем image отличается от container?** Image неизменяемый шаблон из слоёв; container запущенный экземпляр с собственным слоем для записи.
- **Почему `package.json` копируют раньше кода?** Кэш слоёв: зависимости меняются редко, код часто, и `npm ci` не повторяется на каждую правку.
- **Что такое volume?** Хранилище вне файловой системы контейнера: данные БД переживают пересоздание, а код можно монтировать для hot reload.
- **Compose в проде используют?** На одном хосте да. Для масштабирования и самолечения нужен оркестратор: Kubernetes, ECS, Swarm.
