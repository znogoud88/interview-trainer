## Что это
**Коротко:** Путь коммита: push → CI прогоняет lint, typecheck, тесты и сборку → собирается артефакт (бандл или Docker image) → он выкатывается на staging → после проверки в прод. CI (continuous integration) это проверки на каждый коммит. CD это либо continuous delivery (всё готово к релизу, в прод жмут кнопкой), либо continuous deployment (в прод катится автоматически, без кнопки).

Шаги и зачем каждый:
1. **Push / PR**: код ушёл в репозиторий, запускается pipeline.
2. **CI-проверки**: lint, типы, тесты, build. Каждый ловит свой класс проблем до merge.
3. **Артефакт**: результат сборки, собранный один раз. Именно он поедет дальше, не пересобираем на каждом окружении.
4. **Preview environment**: для фронта каждый PR получает свой живой URL (Vercel, Netlify из коробки, или свой стенд). Ревью глазами, QA до merge, дизайнер смотрит сам.
5. **Staging**: окружение, похожее на прод, с тестовыми данными. Последняя проверка связки.
6. **Production**: деплой, мониторинг после, возможность отката.

Delivery vs deployment: разница в последнем шаге. Delivery: pipeline довёл до состояния «можно релизить», человек решает когда. Deployment: зелёный main сам уезжает в прод. Второе требует доверия к тестам, feature flags и быстрого отката.

## Пример
Типичный pipeline фронтового проекта:
```
PR открыт     → lint + typecheck + tests + build → preview URL для PR
merge в main  → build артефакта → deploy на staging → smoke E2E
tag / кнопка  → deploy того же артефакта в prod → алерты, мониторинг
```
Интервьюер на вопросе «расскажи свой pipeline» слушает не термины, а понимание: можешь ли ты рассказать свой процесс по шагам и объяснить, зачем каждый.

## Подводные камни
- Пересборка на каждом окружении: на staging тестировали один артефакт, в прод поехал другой. Собирать один раз, промоутить дальше.
- Preview environments с общей базой: ломают друг друга миграциями и данными. Нужны сиды или изолированные данные.
- «У нас CD» в значении «деплоим руками по пятницам» на собесе выдаёт заучку.
- Красный флаг: не знать, что происходит с кодом после merge. Даже junior должен уметь рассказать путь коммита в прод хотя бы в общих чертах.

## Вопросы вдогонку
- **Чем отличается continuous delivery от continuous deployment?** Delivery: готово, но в прод по кнопке. Deployment: автоматически, без кнопки.
- **Зачем staging, если есть preview на каждый PR?** Preview проверяет одну ветку. Staging проверяет интегрированный main на prod-подобной инфраструктуре.
- **Что такое артефакт?** Результат сборки (бандл, Docker image), который не меняется между окружениями; конфиг подаётся снаружи.
- **Как preview environments работают технически?** На каждый PR собирается своя версия и выкладывается на уникальный URL, по закрытию PR удаляется.
