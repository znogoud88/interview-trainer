## Что это
**Коротко:** На каждый PR в CI идут lint, typecheck, unit и integration тесты, build и E2E-смоук, в порядке от быстрого к медленному. Принцип fail fast: нет смысла гонять E2E на 20 минут, если линт красный через 30 секунд. PR блокируется, пока всё не зелёное; полный тяжёлый сьют идёт по расписанию.

Что ловит каждый шаг:
- **Lint** (ESLint, Prettier, stylelint): стиль, неиспользуемые импорты, подозрительные паттерны. Секунды.
- **Typecheck** (`tsc --noEmit`): ошибки типов, которые бандлер на esbuild или swc молча пропустит, потому что он только стрипает типы.
- **Unit и integration** (Vitest/Jest): логика и поведение компонентов. Минуты.
- **Build**: приложение вообще собирается, импорты резолвятся, env-переменные на месте. Отдельный класс ошибок, тесты его не ловят.
- **E2E smoke** (Playwright): 3-5 критичных путей на собранном приложении. Самое медленное и хрупкое, поэтому последнее.

Дальше от PR: полный E2E-сьют, visual regression, Lighthouse, аудит зависимостей идут по расписанию (ночью) или на merge в main, а не на каждый пуш.

В монорепе: гонять только affected (Nx, Turborepo). Поменял пакет `ui`, прогнались тесты `ui` и тех, кто от него зависит. Иначе CI на монорепе живёт час.

## Пример
```yaml
# GitHub Actions, упрощённо
jobs:
  quick:            # параллельно, всё быстрое
    steps: [lint, typecheck]
  test:
    needs: quick    # не запускаем, если быстрое упало
    steps: [unit + integration]
  build:
    needs: quick
    steps: [build, upload artifact]
  e2e-smoke:
    needs: [test, build]
    steps: [download artifact, playwright smoke]
```
Lint и typecheck независимы, их можно пускать параллельно. Build тоже не зависит от тестов. E2E ждёт артефакт сборки, чтобы не собирать дважды.

## Подводные камни
- Нет кэша на `node_modules` и build-кэша: каждый прогон ставит зависимости с нуля, CI тормозит, люди начинают мержить мимо.
- Все шаги в одной последовательной джобе: lint ждёт тесты, тесты ждут сборку. Параллель там, где нет зависимости.
- Флаки-E2E блокирует PR: команда учится жать «rerun». Смоук должен быть маленьким и стабильным, остальное по расписанию.
- `continue-on-error` на тестах «чтобы не мешали»: это уже не проверка.
- Красный флаг на собесе: перечислить шаги без объяснения, что каждый ловит. Интервьюер ждёт осмысленности: «typecheck отдельно, потому что Vite не проверяет типы».

## Вопросы вдогонку
- **Зачем typecheck отдельно, если есть build?** Vite, esbuild, swc не проверяют типы, только убирают их. `tsc --noEmit` это отдельный шаг.
- **Что такое affected в монорепе?** Запуск тестов и сборки только для пакетов, затронутых изменением, по графу зависимостей.
- **Что делать с E2E, которые идут 30 минут?** Смоук на PR, полный сьют по расписанию, шардинг по воркерам, параллель.
- **Что блокирует merge, а что нет?** Блокируют быстрые и стабильные проверки. Долгие и шумные (visual, полный E2E) репортят, но не держат PR.
