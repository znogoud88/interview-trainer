## Что это
**Коротко:** Скринридер объявляет то, где сейчас фокус, и больше ничего. Три места, где это ломается: форма без связанных label и ошибок (поле объявляется как «edit text» без имени), динамические изменения (корзина обновилась молча) и SPA-переход (URL сменился, страница визуально другая, скринридер молчит, потому что перезагрузки не было). Лечится label и `aria-describedby`, `aria-live` и управлением фокусом при навигации.

Доступная форма:
- У каждого поля label, связанный через `for`/`id` (или обёртка `<label>`). Placeholder это не label: пропадает при вводе, низкий контраст, скринридер читает не всегда.
- Ошибка рядом с полем, привязана через `aria-describedby`, поле помечено `aria-invalid="true"`. Тогда при фокусе на поле скринридер читает и имя, и ошибку.
- После submit с ошибками: фокус на первое невалидное поле или объявление «3 ошибки» через live region. Иначе кнопка нажалась и тишина.
- Группы (радио, чекбоксы, адрес) в `<fieldset>` с `<legend>`, иначе «Да» и «Нет» объявляются без вопроса.
- `autocomplete="email"`, `"tel"`, `"postal-code"`: браузер подставляет, людям с моторикой и когнитивными меньше печатать. Это критерий WCAG AA.

aria-live:
- Регион, изменения в котором скринридер объявляет сам, без переноса фокуса.
- `polite`: дождётся паузы (товар добавлен в корзину, найдено 12 результатов, сохранено).
- `assertive`: прерывает сразу (сессия истекает, ошибка оплаты). Использовать редко.
- `role="status"` это polite, `role="alert"` это assertive, короче и с нужной семантикой.
- Регион должен существовать в DOM заранее, пустым, а менять нужно текст внутри. Если вставлять регион вместе с текстом, многие скринридеры не объявят.

SPA-навигация: роутер поменял DOM, но `document.title` старый, фокус остался на ссылке в меню (или слетел в body), скринридер ничего не сказал. Нужно: обновить title, перенести фокус на `<h1>` или `<main>` с `tabindex="-1"`, или объявить «Перешли на страницу Корзина» через live region. Next.js и Angular Router умеют часть этого, но проверять нужно.

## Пример
```jsx
// ❌ placeholder вместо label, ошибка не связана с полем
<input placeholder="Email" />
<span className="error">Неверный email</span>

// ✅ имя, ошибка и состояние читаются при фокусе на поле
<label htmlFor="email">Email</label>
<input id="email" type="email" autoComplete="email"
       aria-invalid={!!error} aria-describedby="email-err" />
<p id="email-err" role="alert">{error}</p>

// ✅ live region для действий без перехода, регион есть всегда, меняется текст
<div role="status" className="visually-hidden">{message}</div>
// setMessage('Товар добавлен в корзину') после клика
```

## Подводные камни
- Визуально скрытый live region нельзя прятать через `display: none` или `visibility: hidden`, он выпадет из accessibility tree. Нужен класс visually-hidden (clip, 1px, overflow hidden).
- Слишком болтливый live region (каждый символ в поиске, каждый тик таймера) хуже, чем его отсутствие. Объявлять результат, а не процесс, и с debounce.
- Toast на 3 секунды: скринридер объявит, но слабовидящий с зумом может не успеть прочитать. Давать закрыть руками или держать дольше.
- Ошибка только красной рамкой это нарушение сразу двух правил: цвет как единственный носитель смысла и нет текста для скринридера.
- Красный флаг на собесе: «ошибки показываем красной рамкой». Интервьюер хочет текст ошибки, связь с полем и объявление.

## Вопросы вдогонку
- **Чем `role="alert"` отличается от `aria-live="assertive"`?** Практически то же: alert это assertive плюс `aria-atomic="true"`. alert для ошибок, status для нейтральных сообщений.
- **Что такое `aria-atomic`?** Объявлять весь регион целиком при любом изменении, а не только изменившийся кусок. Нужно для «3 из 10», чтобы не прочитало просто «3».
- **Как объявить загрузку?** `aria-busy="true"` на контейнере или status-регион «Загружаем...», потом «Загружено 20 товаров».
- **Как сделать skip link в SPA?** Тот же `<a href="#main">` первым в DOM, плюс при роутинге фокус на main, чтобы Tab начинался с контента, а не с меню.
